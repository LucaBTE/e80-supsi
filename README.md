# e80-supsi

React + FastAPI application using a small preconfigured Neo4j database and Gemini. The seed supplies projects, processes, people, systems, documents and source excerpts. Questions, graph queries and reports are generated by Gemini; there are no canned answers in the application.

## Start the seeded application

Requires Docker Compose, Python 3.12+, uv and Node.js 22.18+.

Run from the repository root:

```bash
uv sync
test -f .env || cp .env.example .env
npm --prefix frontend ci
npm --prefix frontend run build
docker compose up -d --wait
uv run e80kb seed
uv run e80kb serve
```

Open **http://127.0.0.1:8000**. FastAPI serves the frontend and the API together. API documentation is at http://127.0.0.1:8000/docs.

The root `.env` must contain these database settings, matching `compose.yaml`, and your own Gemini key:

```dotenv
NEO4J_URI=bolt://localhost:7688
NEO4J_USER=neo4j
NEO4J_PASSWORD=e80-demo-password
GOOGLE_API_KEY=your-google-api-key
E80KB_MODEL=gemini-flash-latest
E80KB_GROUPS=Internal
```

Keep an existing Gemini key when editing `.env`. Variables exported in the shell override `.env`; update or unset old Neo4j overrides if the application connects to the wrong instance.

The Compose project uses its own database volume and ports **7688** (Bolt) and **7475** (Neo4j Browser). It can coexist with an existing Neo4j on 7687/7474 without changing that database or its password. The sample username/password are `neo4j` / `e80-demo-password`.

`e80kb seed` creates indexes, loads `seed.cypher` and prints node, relationship, document and chunk counts. It does not parse files, run ingestion or call an LLM. It uses `MERGE`, so rerunning it on the sample database does not duplicate the seeded records or delete existing data. The seed data statements are committed in one transaction. For a different seed, use `uv run e80kb seed --file path/to/seed.cypher`.

The seed includes 9 sample document records and 10 excerpts. Some passages are explicitly marked as illustrative. Links in the interface open the stored document excerpts as text; original PDF/Word files are not required. Gemini uses the graph and these excerpts to generate answers with source references.

## Daily use

After the first setup:

```bash
docker compose up -d --wait
uv run e80kb serve
```

To stop the sample database while preserving its contents:

```bash
docker compose stop
```

To verify services and ask a question:

```bash
curl http://127.0.0.1:8000/api/health
uv run e80kb ask "Who should be involved in a change to Salesforce?"
uv run e80kb doc impact Project "Document Automation"
```

The interface, generated answers and default reports are in English. Original source names, codes and quotations retain their original language. The UI has process and project catalogs, impact analysis and document questions. Analysis and information tabs call the same real question-answering API. Selecting an entity opens its graph relations and excerpts; its detail panel can generate and download a Markdown impact report with source references. Missing metadata and confidence scores are shown as unavailable.

## Development

Terminal 1, from the repository root:

```bash
uv run uvicorn e80kb.api:app --reload --host 127.0.0.1 --port 8000
```

Terminal 2:

```bash
npm --prefix frontend run dev
```

Open http://127.0.0.1:5173. Vite proxies `/api`, `/docs` and `/openapi.json` to FastAPI. Set `E80KB_API_TARGET` in `frontend/.env.local` if using a different backend address. Keep database and Gemini credentials in the root `.env`.

For the single-process application, rebuild after frontend changes and restart the backend after the first build:

```bash
npm --prefix frontend run build
uv run e80kb serve
```

## Verification

```bash
uv run pytest
npm --prefix frontend test
npm --prefix frontend run build
```

## Troubleshooting

- `Unsupported authentication token, missing key scheme`: the Neo4j password is empty. Use the settings above for the isolated sample database. The CLI now reports authentication failures without a Python traceback and checks connectivity before starting the server.
- An existing server on port 8000 must be stopped with Ctrl+C and restarted to pick up code and `.env` changes.
- A successful build only checks frontend compilation. `/api/health` verifies Neo4j connectivity.
- Gemini HTTP 429 indicates a rate limit or quota problem. The API returns `Retry-After` after retries; no mocked answer is substituted. HTTP 502 indicates another generation failure, and HTTP 503 indicates missing configuration or database unavailability.
- `NEO4J_AUTH` initializes a new database; changing it does not reset the password in an existing volume. The supplied Compose volume is separate from the previously used database.
- Refresh the catalog in the interface after reloading the seed. The catalog is bounded to 1000 nodes and 5000 relationships by default; natural-language questions query the full database.

## Model and limitations

`src/e80kb/schema.py` defines the graph labels, keys and relationships. Domain entities carry `__Entity__`; source links follow `(entity)-[:FROM_CHUNK]->(Chunk)-[:FROM_DOCUMENT]->(Document)` and `NEXT_CHUNK`. Canonical aliases live in `aliases.py`.

Gemini generates a Cypher query, static checks restrict it, and the backend executes it with a timeout. Source excerpts are filtered by `Document.acl`, then Gemini generates a cited answer. Read access mode is not an authorization boundary. Neo4j Community does not provide full graph-level ACL isolation, and no user login is implemented: every request uses `E80KB_GROUPS`.

Full-text search is used without embeddings. Relationships have no per-chunk provenance; the UI does not invent edge citations or confidence scores. Existing ingestion modules remain in the source tree but are not used by this seeded setup. Old frontend mock datasets are design references and are not used to answer questions.
